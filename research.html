  • SASD: Source-Aware Self-Distillation

    In progress

    A training time defense against prompt injection

    Deployed LLM systems put untrusted text into the same context window as the developer's instructions. Retrieved documents, tool output and web pages all arrive with the same apparent authority, so defenses end up at inference time as classifiers or delimiters that an attacker can phrase around.

    SASD moves the problem into training. The model is distilled with a multi teacher KL divergence objective against teachers that see the same task under different source conditions, so it learns to reproduce the behavior of a teacher that was never shown the injected span.

    I am currently building the training pipeline and the injection benchmark suite, targeting a submission to NeurIPS or ICLR.

  • Refusal mechanisms & representation engineering

    Ongoing

    Early-stage group research on refusal representations · with Prof. Nadir Durrani

    A running review of how safety behavior is encoded inside language models. It starts from the finding that refusal is mediated by a single direction in activation space, one that transfers across languages and decomposes into sparse interpretable features, then moves through methods that turn that direction into a defense: Circuit Breakers rerouting harmful representations during training, SafeSteer distilling a steered model's own refusal signal onto a small set of tokens rather than the whole vocabulary. Rogue Scalpel complicates the picture further, showing that random or unrelated vectors break refusal just as reliably, which questions whether a single clean direction is really what's being controlled.

    Presented biweekly to a small research group.

  • Visual similarity and complementary product recommendation

    In progress

    Mitacs Globalink Research Internship, Algoma University · with Prof. Mahreen Nasir

    Can a single, lightweight embedding be steered at inference time between visual similarity (substitutes) and stylistic compatibility (complements), rather than relying on separate models for each? The question extends to whether this controllable representation can match or beat published complementary item retrieval baselines while offering a control existing fixed embedding methods don't.

    I benchmarked four visual encoders (ResNet50, CLIP, FashionCLIP, SigLIP) on Amazon Review Data 2018 and DeepFashion, establishing SigLIP as the strongest backbone, then investigated learning a genuine substitute/complement distinction from Amazon co-purchase behavior and Polyvore Outfits. I built a controllable projection head on top of SigLIP and verified its retrieval behavior shifts smoothly between substitute and complement modes from a single trained model.

    I am now reproducing standard retrieval baselines (CSA-Net) under my own evaluation protocol to benchmark the model fairly, and writing up the results.

  • Qalb Post-Train: Urdu math reasoning via RL with verifiable rewards

    Completed

    Rejection sampling → SFT → GRPO

    Reasoning post-training is well documented for English models with industrial compute. This project asks what survives at the other extreme, on a low-resource language and limited GPU credits.

    Starting from Qalb-1.0-8B-Instruct, a Llama-3.1-8B continued-pretrained on ~1.97B Urdu and English tokens, I carried the model past instruction tuning in three stages: rejection sampling to build a cold-start corpus of correct traces, a short SFT pass to install the output format, then GRPO against a rule-based reward. The model reasons in Urdu inside <think>…</think> tags and then emits a numeric answer that can be checked automatically. The reward is digit-normalized answer matching against GSM8K-Urdu, with no judge model and no paid API calls. Everything runs on serverless GPUs via Modal.

    94.7% format adherence, RFT-merged checkpoint on GSM8K-Urdu

  • shellsim: GRPO terminal agent trained against a simulated shell

    Completed

    World model environments for agent RL

    Training a terminal agent with RL normally means thousands of rollouts against a real shell inside a container, which is slow to parallelize and awkward to sandbox. shellsim removes the container: the environment is a language model (Qwen-AgentWorld-35B-A3B) trained to simulate a shell, and the policy (Qwen2.5-3B-Instruct) is optimized with GRPO against that simulation.

    The environment is learned but the reward is not. Every task variant is scored by a declarative verifier (env/verifier.py) rather than by world model output or a judge model, so the policy cannot score well by convincing the simulator.
